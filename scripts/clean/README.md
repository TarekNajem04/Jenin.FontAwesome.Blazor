# Jenin FontAwesome Repository Cleanup Tool

The `clean.ps1` script is a repository maintenance tool used to remove generated files and directories created during development and testing.

The tool is designed to keep the repository clean by removing:

- Build output folders.
- Test result folders.
- Code coverage reports.
- Temporary generated artifacts.

---

## Safety First

The cleanup tool is intentionally **safe by default**.

Running:

```powershell
.\clean.ps1
```

does **not delete anything**.

It only displays the directories that would be removed.

Actual deletion requires explicit execution:

```powershell
.\clean.ps1 -Execute
```

---

# Requirements

* PowerShell 7+ recommended.
* A .NET solution file must exist in the repository:

```
*.sln
```

or

```
*.slnx
```

The script uses the solution file to automatically locate the repository root.

---

# Folder Structure

The cleanup tool contains:

```
clean/
│
├── clean.ps1
├── clean.config.json
├── clean.schema.json
└── README.md
```

## Files

### clean.ps1

The main cleanup script.

Responsibilities:

* Locate repository root.
* Load cleanup configuration.
* Find matching directories.
* Preview or remove generated content.

---

### clean.config.json

Contains cleanup rules.

Example:

```json
{
  "version": 2,

  "directories": {
    "include": [
      "bin",
      "obj",
      "output",
      "artifacts",
      "TestResults*",
      "*Coverage*",
      "_site",
      "api",
      ".vs",
      ".sonarqube"
    ],

    "exclude": [
      ".git",
      ".github"
    ]
  },

  "files": {
    "include": [
      "*.user",
      "*.suo",
      "*.userosscache",
      "*.coverage",
      "*.coveragexml",
      "*.trx",
      "coverage*.info",
      "Thumbs.db",
      ".DS_Store"
    ],

    "exclude": []
  }
}
```

---

### clean.schema.json

JSON schema used by editors to validate:

* Configuration structure.
* Allowed properties.
* Value types.

# Usage

## Preview Cleanup

Recommended first step:

```powershell
.\clean.ps1
```

Example output:

```
Mode: Preview

Would delete:
C:\Projects\Jenin.FontAwesome.Blazor\src\App\bin

Would delete:
C:\Projects\Jenin.FontAwesome.Blazor\Tests\TestResults
```

No changes are made.

---

# Execute Cleanup

To permanently remove matching directories:

```powershell
.\clean.ps1 -Execute
```

The script will request confirmation before deleting files.

---

# Skip Confirmation

Useful for automation environments:

```powershell
.\clean.ps1 -Execute -SkipConfirmation
```

Example:

* GitHub Actions
* Azure DevOps pipelines
* Local automation scripts

---

# Verbose Output

To see detailed processing information:

```powershell
.\clean.ps1 -Verbose
```

Example:

```
Searching:
bin

Searching:
obj

Solution found:
Jenin.FontAwesome.Blazor.slnx
```

---

# Adding Temporary Patterns

Additional patterns can be supplied without modifying `clean.config.json`.

Example:

```powershell
.\clean.ps1 -Include "logs*"
```

This will include:

```
logs
logs-old
logs-2026
```

for the current execution only.

File patterns can be added the same way:

```powershell
.\clean.ps1 -IncludeFiles "*.log"
```

---

# Adding Temporary Exclusions

Additional exclusions can also be provided:

```powershell
.\clean.ps1 -Exclude "important-folder"
```

The folder will be preserved during cleanup.

# Cleanup Rules

The default configuration removes:

## Build Output

```
bin
obj
```

Generated by:

* dotnet build
* dotnet test
* Visual Studio

---

## Test Results

Patterns:

```
TestResults*
```

Examples:

```
TestResults
TestResultsLocal
TestResults_2026
```

---

## Coverage Reports

Pattern:

```
*Coverage*
```

Examples:

```
TestCoverageReport
TestCoverageReportDetailed
CoverageResults
```

---

## Generated Documentation and API Metadata

Patterns:

```
docs/_site
```

`docs/_site` is the generated DocFX output (site and API metadata); it is git-ignored and rebuilt by:

```powershell
dotnet tool restore
dotnet docfx docs/docfx.json
```

---

## Local Package Feed and Coverage Output

Pattern:

```
artifacts
```

This contains the local NuGet feed and generated coverage reports. Deleting it is safe; rebuild
packages with `./build.sh Release pack` (or `dotnet pack` on a package project).

---

## IDE and Analysis Caches

Patterns:

```
.vs
.sonarqube
```

`.vs` is the Visual Studio local cache; close Visual Studio before deleting it. `.sonarqube` is the
local Sonar analysis cache; close the analysis before deleting it. Both are regenerated on demand.

---

## User-Specific and Operating-System Files

Patterns:

```
*.user
*.suo
*.userosscache
*.coverage
*.coveragexml
*.trx
coverage*.info
Thumbs.db
.DS_Store
```

These are per-user, coverage, or operating-system files. They are not source and are regenerated by
the IDE, test runner, or operating system.

---

# Protected Directories

The script will never intentionally remove:

```
src
tests
scripts
scripts/coverage
templates
eng
samples
docs
private
.config
badges
.git
.github
```

These folders contain source code, documentation, build-time tools, or repository configuration.
The `.git`, `.github`, and `private` trees are protected recursively; `bin` and `obj` folders inside
source projects are still cleaned.

# Design Principles

This tool follows these principles:

## Safe by Default

No destructive operation happens without:

```powershell
-Execute
```

---

## Configuration Driven

Cleanup rules are stored in:

```
clean.config.json
```

The script does not contain project-specific folder names.

---

## Repository Independent

The script automatically detects the repository root by searching for:

```
*.sln
*.slnx
```

This allows the tool to work even if the repository location changes.

---

## CI/CD Friendly

The script supports non-interactive execution:

```powershell
.\clean.ps1 -Execute -SkipConfirmation
```

# Troubleshooting

## Error: Solution file not found

Example:

```
Unable to find repository root.
No *.sln or *.slnx file found.
```

Solution:

Run the script from inside the solution directory.

Example:

```
Jenin.FontAwesome.Blazor
│
├── Jenin.FontAwesome.Blazor.slnx
│
└── scripts
    └── clean
        └── clean.ps1
```

---

## Error: Configuration file not found

Ensure that:

```
clean.config.json
```

exists next to:

```
clean.ps1
```

or specify another file:

```powershell
.\clean.ps1 -Configuration .\my-clean.json
```
