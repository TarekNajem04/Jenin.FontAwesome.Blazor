# Analyzer diagnostics (`Jenin.FontAwesome.Blazor.Analyzers`)

Compile-time guidance for the typed API, shipped as the optional
`Jenin.FontAwesome.Blazor.Analyzers` package. Nothing here ever errors:
every diagnostic defaults to `Warning` and honors `.editorconfig` severity, e.g.

```ini
# .editorconfig — per-project tuning (licensed Pro assets, intentional demos)
dotnet_diagnostic.JFA1003.severity = none
```

| ID | Title | Default | Fires when | Fix / action |
|---|---|---|---|---|
| JFA1001 | Unknown Font Awesome icon name | Warning | `IconName` / `MaskIconName` (or `[Icon("…")]`) is not a known FA 7 Free name or alias | Fix the spelling or use an `IconNames` constant; renames become compile errors |
| JFA1002 | Raw Font Awesome classes in a name position | Warning | A name position holds a full class string (`"fa-solid fa-house"`) | Code fix rewrites it to `IconNames.Solid.House` (offered for exact two-token solid/regular/brands strings that exist); longer strings need manual splitting into `IconSize` etc. |
| JFA1003 | Pro-only style without licensed assets | Warning | `IconStyle` is `Light`, `Thin`, or `Duotone`, or `Typeface` is `Sharp`, `Duotone`, or `SharpDuotone` | Host licensed Pro assets (then suppress per project) or switch style; Free hosts fall back to the classic style |

Scope notes:

- Only **name positions** are analyzed: `IconName` / `MaskIconName` assignments and
  initializers, the `Icon` attribute's name argument, and the Razor-generated
  `AddAttribute("IconName" | "MaskIconName", …)` shape. Arbitrary `class="fa-…"` markup
  (for example documentation snippets showing raw Font Awesome HTML) is deliberately out
  of scope — flagging those would be noise.
- The known-name set is the vendored FA 7.3.1 metadata **including legacy aliases**
  (`fa-home` still renders via the FA engine), generated by
  `eng/generate-analyzer-icon-names.ps1` into the analyzer (`-Verify` gates drift in CI).
- Pro-only detection is syntactic: any `Light`/`Thin`/`Duotone` style (or
  `Sharp`/`Duotone`/`SharpDuotone` typeface) is flagged because the compiler cannot know
  whether the host licensed Pro assets. Suppress with `dotnet_diagnostic.JFA1003.severity`
  (project-wide or `#pragma warning disable JFA1003` around an intentional demo).
- In Razor files the diagnostic location comes from the generated code; the code fix
  applies in C# sources — in Razor, make the same edit by hand (the message shows it).
